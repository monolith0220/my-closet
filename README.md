# My Closet

Vue 3 + TypeScript + Vite で作った、スマートフォン向けの洋服管理 PWA です。メール認証、写真付きの登録・編集・削除、お気に入り、5段階のレーティング、上下コーデの保存、検索と並び替えに対応します。ユニクロ・GU の商品ページからの情報取得や非公式スクレイピングは行いません。商品番号と商品 URL は手入力で保存できます。

クローゼットは写真を横4列で表示し、画面上部に検索ボタンと追加ボタンを置きます。アイテムを長押しすると複数選択に切り替わり、下部ナビの直上に固定される操作バーからまとめて削除できます。削除前に確認し、削除した服は非表示にします。追加ボタンから1着の登録、購入履歴の一括登録、写真の一括追加を選べます。写真は32着ずつ読み込みます。検索はクローゼット上のダイアログで行い、商品名・大分類・小分類・袖丈・ブランド・ユニクロライン・カラー・お気に入り・並び順を選べます。「クローゼットに表示」を押すと条件に一致する全アイテムを表示し、読み込み済みの一覧と画像URLを維持します。トップスは種類と半袖・長袖の両方で絞れ、袖丈を商品名から判断できないものは「不明」に分類します。以前の「小物」「バッグ」「シューズ」などの登録データも表示時に対応するグループへまとめます。

お気に入りと0〜5のレーティングは詳細画面から変更できます。アイテム詳細を開いた回数はアカウント内で記録し、画面には表示しません。下部メニューの「コーデ」では上下の組み合わせを保存できます。「AIコーデ」画面では閲覧回数が少ないトップス・アウターとボトムスを優先して3組を提案し、そのまま保存できます。現在の提案は閲覧回数を使う決定的な組み合わせで、生成AIによるスタイル判定は行いません。詳細画面では購入日を表示し、`MEN M` などのサイズは `M` のように表示します。商品番号は保存し、詳細画面には表示しません。編集画面の写真は全体が見えるよう縮小表示します。

ユニクロUとユニクロCは「ユニクロライン」で分類します。既存データはブランド名または商品名にライン名が明記されている場合だけ自動分類し、判別できない商品は未設定のままにします。登録・編集画面から手動で指定できます。

## 必要なもの

- Node.js 22.18 以上の 22 系、または 24.11 以上と npm
- Supabase プロジェクト（ローカルで試す場合は Docker と Supabase CLI）

## 起動

```bash
npm install
cp .env.example .env.local
npm run dev
```

Windows PowerShell の場合、コピーは `Copy-Item .env.example .env.local` を使えます。Vite が表示する URL（通常 `http://localhost:5173`）を開いてください。`npm run build` で型チェックと本番ビルド、`npm run preview` でビルド結果の確認ができます。

`.env.local` が空でも開発サーバーとビルドは動きます。その場合、画面に Supabase の設定手順が表示され、ログインやデータ保存はできません。ダミーの認証成功や架空の洋服データは表示しません。

洋服の写真は JPEG・PNG・WebP（最大 10 MB）に対応します。

### ユニクロ購入履歴の一括追加

クローゼットの「ユニクロの購入履歴からまとめて追加」から、商品名・カテゴリ・カラー・サイズ・商品番号・商品 URL・購入日の CSV またはタブ区切りの表を取り込めます。先頭行は `商品名,カテゴリ,カラー,サイズ,商品番号,商品URL,購入日` としてください。候補を確認・編集・除外してから一括保存します。登録済みと同じ商品番号・カラー・サイズの候補には注意表示が出ます。画像は後から追加できます。

ユニクロのアカウントとの直接連携や商品ページのスクレイピングは行いません。ユニクロの[購入履歴「商品一覧」](https://www.uniqlo.com/jp/ja/member/orders/products)を本人が確認し、取り込む商品の情報だけを表にしてください。返品・交換は公式の購入履歴に反映されないため、所有していない商品は候補から外してください。CSV/TSVの内容はブラウザー内で解析し、選択した洋服の項目だけを Supabase に保存します。

### ユニクロの商品 URL

日本向けのユニクロ公式商品 URL（例：`https://www.uniqlo.com/jp/ja/products/E478339-000/00?colorDisplayCode=01&sizeDisplayCode=004`）を登録画面に貼ると、URL の文字列からブランド `UNIQLO` と商品番号 `478339` を入力補助します。URL にカラー・サイズのコードがあれば参考表示します。商品名、日本語の色名、実際に購入したサイズは URL だけでは確定できないため、商品ページやタグを見て入力してください。ユニクロへの通信は行いません。

### 写真の一括追加

クローゼットの「購入履歴の写真をまとめて追加」から、登録済みの購入履歴アイテムへ画像ファイルを一括で紐付けられます。画像ファイルを選び、タブ区切りの対応表を貼り付けてください。先頭行は `商品番号<TAB>カラー<TAB>サイズ<TAB>購入日<TAB>画像ファイル名` です。カラーは購入履歴に表示される元の表記（例：`09 BLACK`）を使います。商品番号・カラー・サイズ・購入日がすべて一致する登録済みアイテムだけを候補にし、同じ購入情報の登録が複数ある場合や、すでに写真がある場合は更新しません。

反映する画像は本人が利用できるものを選んでください。アプリはユニクロの商品ページや購入履歴から画像を自動取得しません。画像はログイン中のユーザー専用の非公開 Supabase Storage に保存され、一覧表示用の署名付き URL は表示する32件ずつ発行します。ユニクロ公式は[掲載画像の個人サイトでの使用を控えるよう案内](https://faq.uniqlo.com/articles/Knowledge/100001721/)しています。

## Supabase の設定

1. [Supabase](https://supabase.com/dashboard) でプロジェクトを作成します。
2. SQL マイグレーション `supabase/migrations/` を適用します。Supabase CLI を使う場合は次のコマンドで接続・反映できます。

   ```bash
   npx supabase login
   npx supabase link --project-ref <Project ID>
   npx supabase db push
   ```

   既存のプロジェクトも `20261029000000_closet_features.sql` と `20261030000000_clothing_engagement.sql` を順に適用してください。後者はユニクロライン・レーティング・閲覧回数の列と、本人の閲覧回数だけを増やす関数を追加します。適用前は今回の機能を保存できません。

3. Dashboard の **Project Settings → API** にある Project URL と公開用 `anon` / publishable key を `.env.local` に設定します。

   ```dotenv
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_ANON_KEY=<public-anon-or-publishable-key>
   ```

4. Supabase Dashboard の **Authentication → Providers** で Email を有効にします。アプリの新規登録フォームからメールアドレスとパスワードでアカウントを作れます。メール確認を有効にしている場合は、届いた確認リンクを開いてからログインしてください。必要に応じて **Authentication → URL Configuration** に開発時の `http://localhost:5173` と公開先 URL を追加します。
5. 開発サーバーを再起動し、ログインして洋服を登録してください。

**秘密情報:** `VITE_` で始まる環境変数はブラウザーのバンドルに含まれます。ここには公開用キーだけを入れ、`service_role` キー、DB パスワード、個人トークンは絶対に設定しないでください。`.env.local` は Git 対象外です。

### ローカル Supabase で試す

Docker を起動してから、次を実行します。

```bash
npx supabase start
npx supabase status
```

`status` の API URL と `anon key` を `.env.local` の値に使います。`supabase start` 時にマイグレーションが適用され、`clothing-images` という**非公開** Storage バケットが作成されます。画像パスは `<user_id>/<uuid>.<拡張子>` 形式で、自分のフォルダー以外への操作は RLS で拒否されます。画像表示には短時間有効な署名付き URL を使います。

## データとアクセス制御

- `clothing_items`: 洋服、画像パス、商品番号・URL、購入日、お気に入り、レーティング、閲覧回数、ユニクロライン、シーズンなど
- `outfits`: 保存した上下コーデと将来のコーデ提案データ
- `outfit_items`: コーデと洋服の関連（上下コーデは `top`・`bottom` 役割）

主キーは UUID、`user_id` は Supabase Auth のユーザー ID を参照します。各テーブルで RLS を有効にし、所有者の行だけが読み書きできます。`outfit_items` には関連元・関連先と同じユーザーであることを保証する制約もあります。

## アクセス制御テスト

Supabase CLI と Docker が使える環境で実行します。

```bash
npx supabase start
npx supabase test db
```

`supabase/tests/` の pgTAP 統合テストで、異なる 2 ユーザー間の `SELECT`、`INSERT`、`UPDATE`、`DELETE`、コーデ関連付け、Storage オブジェクトへのアクセス拒否を確認します。これは実際の PostgreSQL/RLS に対するテストです。Docker や CLI がない環境ではこのテストは実行できません。

## PWA

本番ビルドには Web App Manifest と Service Worker が含まれます。HTTPS で配信するとホーム画面に追加できます。アプリの静的ファイルはキャッシュされますが、認証・洋服データ・非公開画像の読み書きには接続が必要です。
